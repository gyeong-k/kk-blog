# 데이터가 서버로 어똏게 오는가

- POST = "추가하겠다"라는 행동
  + 추가할 데이터도 같이 보내야
  + 예) “투두를 추가하겠습니다” + “우유 사기”

## 구조
1. 어디로?, 어떤 방식으로?
   - 요청 : req.method (어떤 방식) + req.url(어디로)
2. 실제 데이터
   - request body (요청 본문)
   - 예) 우유 사기
  
## POST는 누가 보내나?
- HTML form
- JavaScript fetch
- API 도구 (예: Postman)

- (참고) 주소창은 보통 GET 요청을 보냄

## url과 method를 같이 검사하기
if (req.method === "GET" && req.url === "/") {  ... }

## 배열 사용하기
- json : 자료구조라기보단, 데이터 표현 방식!
- 여러 개의 할일 목록을 저장하기 위해 배열 사용!
- 배열 : 실제 메모리 안
- JSON : 네트워크로 주고 받을 경우

### 서버 -> 브라우저 데이터 변환
- 배열 자체를 그대로 네트워크로 보내는 게 아니라, 전송 가능한 형태로 바꿔야 함!
  - 브라우저와 서버는 HTTP라는 규칙으로 데이터를 주고 받음
  - 응답은 결국 바이트(문자열 데이터) 로
  - 서버 입장 : 브라우저가 읽을 수 있는 전송용 데이터로 바꿔야
    - JSON.stringify() 사용
      - 배열을 JSON 문자열로 변환 -> 네트워크로 보낼 수 있음
        
res.writeHead(200, { "Content-Type": "application/json; charset=utf-8" });
- writeHead(200, ...) : 응답의 상태 코드(status code) 와 헤더(header)
  - 200 → 요청이 정상 처리됐다는 뜻
- "Content-Type"
  - 지금 보내는 응답이 어떤 종류의 데이터인지
  - application/json : “JSON 데이터입니다”
  - charset=utf-8 : 한글 깨짐 방지용

(핵심) res.end(JSON.stringify(todoList));
- todoList가 배열이라면, 그걸 문자열로 변환
- res.end() = 브라우저로 보내는 데이터
- 자바스크립트 배열 → 네트워크로 보낼 수 있는 문자열

### 서버 내부와 네트워크의 데이터
- 서버 내부
  - 자바스크립트 값
    - 배열
    - 객체
    - 문자열
- 네트워크 전송
  - 문자열(또는 바이트)

### 브라우저 -> 서버
- 브라우저가 서버로 JSON 데이터를 보내면?
  - 예) {"text":"우유 사기"}
- 문자열을 다시 자바스크립트 객체로 바꾸는 작업
